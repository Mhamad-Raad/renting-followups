# Review 2026-10-25: optional area name

## What was built

The owner's decision: the area name is optional, because the client knows each place only by its group (the category) and its renter. An area without a name is shown by its current renter's name everywhere, and as "No name" with no renter. Receipts show the category on the Area line, since the renter has its own line. Names that are filled in stay unique within a category. Migration 004 lets any number of unnamed areas share one category. The Excel import no longer needs the name column (`e9f0e27`, `b1fd3bc`).

## Issues found and how each was fixed

An independent reviewer read the whole change. Three real defects, each fixed in its own commit with a test:

1. **A "name" of only invisible marks** (a lone tatweel or ZWNJ) was refused as a duplicate of an unnamed area, and would have shown as an empty label. Such a name now counts as no name, in the form and in the import (`544358c`).
2. **The activity log renamed old entries** of an unnamed area after the renter changed ("Area added: Bakhtiar" for an area added with Aram). Entries now keep the renter recorded with them (`ae1cc59`).
3. **The report's area picker** could list two entries both called "No name", or the same renter twice. Each entry now shows its category, and areas with the same shown name keep a fixed order everywhere (`f1b7405`).

Also found while testing: **three reminder end-to-end tests failed in the last week of every month**, also before this change. The test area got a month-end reminder as well as a late one. The test now pays the current month, so the counts are the same on any day (`841fea1`).

Left as they are (minor, noted in `DECISIONS.md`): in the printed report and Excel an unnamed area shows the renter in both the Area and Renter columns. Rows without a name are always imported, and the template help says to import such a file only once.

## Regression results

- `npm run check`: typecheck, lint, Prettier and **660 unit tests** pass (new: migration 004 on existing data, unnamed areas in one category, invisible-mark names, renter fallback in reports, the activity log and Excel, the receipt line, stable sorting, import without the name column).
- `npm run test:e2e`: **55 end-to-end tests** pass (new: two unnamed areas shown by their renter, and saving a new area without a name).
- Two tests failed once each at app start in one earlier run (a window closed while launching, and the start-up stall noted in iteration 13). They passed in 51 out of 51 repeated runs afterwards.
- Screens checked in ghost mode: the Areas list and area page in Sorani, the form's hint, Reports in English dark, and a receipt.

## Memory and performance

No new listeners, timers or queries per row. The name rule is a small pure function, and the area page and lists reuse data they already load.
