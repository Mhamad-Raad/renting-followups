# Review 2026-10-21: iterations 4–6

Asked by the owner. Scope: everything since `iter-03` (month status engine, payments, area page and Home), because iterations 4–6 had only their end-of-iteration self-review.

## What was checked

- An independent read of the whole diff (`git diff iter-03...HEAD`) for business-rule bugs, data integrity, IPC validation, React effects and leaks, i18n and RTL, DRY and file size, against ARCHITECTURE.md sections 5–8 and the owner's decisions.
- The running app (ghost mode, 1100×700): keyboard only (Enter opens and saves the payment form, Esc closes, tab order sidebar → header → actions → filter), Arabic-Indic digits typed into an amount, USD cents, a future date received, extra-large text in Sorani on Home, Areas and the area page (no sideways page scroll), reduced motion (boxes fade in 80 ms with no movement), and the "computer date looks wrong" warning with a receipt dated after today.
- `npm run check`, `npm run test:e2e`, and the memory checks of the iteration reviews.

## Found and fixed

| Issue                                                                                                           | Fix                                                                                               |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Lowering the rent of a paid month kept it green but silently dropped the money above the new rent from Received | The price warning now also lists money that would stop counting (`68e6206`)                       |
| If the paid-months check failed, the price change was saved without any warning                                 | Nothing is saved; a plain error is shown (`100a0c4`)                                              |
| A start month with nothing to fill (vacant, or past the 24-month limit) said "more than two years of rent"      | Its own plain message (`bc55cd5`)                                                                 |
| The attention order compared dinars with dollar cents for areas with equal late months                          | Ordered by currency before amount (`5ed7429`)                                                     |
| "Owes" before the amount reads wrongly in Sorani                                                                | Label above the amount (`c0d112d`)                                                                |
| Receipts of a deleted area could still be read by the screen                                                    | Hidden until restored (`46784fd`)                                                                 |
| Price rows for all areas relied on the database returning them oldest first                                     | Always sorted (`8d6ea59`; the database happened to return them in order, so this was a safeguard) |
| Header buttons squeezed their words onto two lines with extra-large text                                        | Buttons wrap under the title (`66167e1`)                                                          |
| Home cards of two currencies were hard to tell apart with large text                                            | Each currency's cards under its name (`710ebc3`)                                                  |
| While typing, the payment preview briefly showed the result for the first digit                                 | Dimmed until it catches up (`2c9b152`)                                                            |
| `payments.ts` over 250 lines                                                                                    | Paid-amount queries moved to `paid.ts` (`refactor(payments)`)                                     |
